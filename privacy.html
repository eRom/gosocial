Privacy Policy

Effective date: October 15, 2026

GoSocial is a personal command-line tool run locally on macOS by its developer, Romain Ecarnot ("I", "me"). Its only user is the developer. This policy explains what data GoSocial handles and how. Using GoSocial requires agreeing to this policy.

Use of YouTube API Services

GoSocial uses YouTube API Services to upload videos to the connected YouTube channel and to manage their metadata. By using GoSocial, you are also subject to the Google Privacy Policy and agree to the YouTube Terms of Service.

Data accessed

After you grant access through Google OAuth, GoSocial accesses:

  • Basic information about your YouTube channel (channel ID and title), to confirm which channel is connected.
  • The videos you upload with GoSocial and their metadata: title, description, tags, thumbnail, playlist, audience and publication settings.

GoSocial does not access your watch history, subscriptions, comments, analytics, or any other account data.

Data stored

  • The OAuth access and refresh tokens, stored only in the macOS Keychain of the computer running GoSocial.
  • Nothing else, apart from the Threads, LinkedIn and X items listed in the sections below. Video files and metadata stay in your local files and are sent directly from your computer to YouTube.

Use of the Threads API

GoSocial also publishes text posts to the developer's own Threads account through the Threads API, using the threads_basic and threads_content_publish scopes and nothing else. It does not read feeds, replies or insights.

  • The only items stored are the Threads app credentials and the access token, kept in the macOS Keychain of the developer's Mac. There is no server, no database and no analytics.
  • Running gosocial auth threads logout deletes the token from the Keychain. Access can also be removed in the Threads settings (Settings > Account > Website permissions).
  • The page threads-callback.html only forwards the sign-in code to the local GoSocial process on 127.0.0.1 and stores nothing.

Use of the LinkedIn API

GoSocial also publishes text posts, and an optional first comment on each post, to the connected LinkedIn member's own profile through the LinkedIn API, using the openid, profile and w_member_social scopes and nothing else. It does not read feeds, connections, messages or analytics.

  • The only items stored, in the macOS Keychain of the developer's Mac and nowhere else, are the app credentials (client ID and secret), the access token, its expiry date, the member identifier (urn:li:person) and the display name. There is no server, no database and no analytics.
  • Only the posts and optional first comments requested by a publication batch are published, on the profile of the connected member.
  • Running gosocial auth linkedin logout asks LinkedIn to revoke the token and deletes it from the Keychain; if LinkedIn cannot be reached, the token is deleted locally and access can be removed in the LinkedIn settings (Settings > Data privacy > Permitted services).
  • The page linkedin-callback.html only forwards the sign-in code to the local GoSocial process on 127.0.0.1 and stores nothing.

Use of the X API

GoSocial also publishes text posts to the connected X account through the X API, using the tweet.read, tweet.write, users.read and offline.access scopes and nothing else. It does not read timelines, followers, messages or analytics.

  • The only items stored, in the macOS Keychain of the developer's Mac and nowhere else, are the app identifier (client ID, there is no secret), the access token, the refresh token, the expiry date of the access token, and the identifier and name of the X account. There is no server, no database and no analytics.
  • Only the posts requested by a publication batch are published, on the connected X account.
  • Running gosocial auth x logout asks X to revoke the token and deletes it from the Keychain; if X cannot be reached, the token is deleted locally and access can be removed in the X settings (Settings > Security and account access > Apps and sessions).
  • The page x-callback.html only forwards the sign-in code to the local GoSocial process on 127.0.0.1 and stores nothing.

Data shared

GoSocial has no server, no database, no analytics and no tracking. It does not collect, sell or share any user data with third parties. YouTube API data is sent only to YouTube. Text you publish to Threads is sent only to Threads. Text you publish to LinkedIn is sent only to LinkedIn. Text you publish to X is sent only to X.

Revoking access and deleting data

  • You can revoke GoSocial's access to your Google account at any time from the Google security settings page: https://security.google.com/settings/security/permissions.
  • Signing out of YouTube in GoSocial deletes the stored tokens from the Keychain immediately.
  • Running gosocial auth threads logout deletes the Threads token from the Keychain. Threads access can also be removed in the Threads settings (Settings > Account > Website permissions).
  • Running gosocial auth linkedin logout asks LinkedIn to revoke the token and deletes it from the Keychain; if LinkedIn cannot be reached, the token is deleted locally and access can be removed in the LinkedIn settings (Settings > Data privacy > Permitted services).
  • Running gosocial auth x logout asks X to revoke the token and deletes it from the Keychain; if X cannot be reached, the token is deleted locally and access can be removed in the X settings (Settings > Security and account access > Apps and sessions).
  • When access is revoked from the Google security settings page, the stored tokens stop working and are deleted from the Keychain the next time GoSocial connects to YouTube.
  • Because GoSocial stores no other data about you, there is nothing else to delete. You can also ask for deletion using the contact below.
